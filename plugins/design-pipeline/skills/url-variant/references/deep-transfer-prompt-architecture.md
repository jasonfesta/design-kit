# Deep Image-to-Image Transfer Prompt Architecture & Two-Pass Conditioning (`url-variant`)

A shallow 4-sentence prompt ("make a variant with new colors and new text") causes image generation models to **regress**: rich interactive diagrams collapse into empty boxes, mobile layouts inherit tiny desktop font sizes, or the mobile variant drifts into a completely different design system than the desktop variant.

`url-variant` prevents regression and "junk" outputs by enforcing:
1. **Mandatory Visual + DOM Inspection Before Prompting** (`read_file` on captured Desktop and Mobile screenshots + `dom/dom-audit.json`).
2. **A Two-Pass Cross-Conditioned Image-to-Image Pipeline** (Pass 1 = Desktop Variant from Desktop Capture; Pass 2 = Mobile Variant conditioned on **both** the Mobile Capture AND the rendered Desktop Variant).
3. **A 10-Section Deep Transfer Prompt Architecture** generated by [plan_and_run_variant.py](../scripts/plan_and_run_variant.py) and enriched by the agent's visual inspection notes.
4. **A Designer-Authored Reinvention Mode** (`--reinvention-mode`) embedded verbatim in Section 2 so the attached screenshot's *role* is explicit (gauge complexity vs. reinterpret central idea vs. sibling refresh).
5. **Single-Variant Testing Default** (`--max-bands-per-surface=1`): exactly **1 Desktop variant + 1 Mobile variant** conditioned on the full-length captures (`0` = per-band generation across the whole page).

---

## 0. Reinvention Modes (Section 2 Core Directive)

| Mode | Auto Dial Range | What the Attached Screenshot Is Used For | What Must Survive |
| :--- | :---: | :--- | :--- |
| `subtle-sibling` | `0.10-0.34` | Spatial cadence reference | Spatial cadence, function, level of finish |
| `central-idea-reinterpretation` | `0.35-0.84` | **The central idea**: "Develop a distinct visual interpretation of the reference's central idea. Preserve what the image communicates and the qualities that make it appealing while independently redesigning how the idea is expressed." | Central concept, intended function, explicit request requirements; otherwise only **subject category, broad emotional tone, and level of finish** |
| `total-reinvention` | `0.85-1.00` | **Complexity gauge only** (`attach_image_only`): "Use the attached reference image ONLY to gauge the level of visual complexity, stylization, and production quality. Everything is available for reinvention." | Nothing literal — comparable sophistication; immediately distinguishable at thumbnail size; redesign any recognizable arrangement, dominant shape, or motif |

The selected mode's full `core_directive` text is written verbatim into every prompt and into `variants/variation-blueprint.md` (`### Core Creative & Reinvention Directive`). On Pass 2 (Mobile), the same directive is applied while locking the visual identity and `comp_and_art_direction` to the rendered Desktop Variant.

## 1. Two-Pass Cross-Conditioned Image-to-Image Transfer

```text
PASS 1: DESKTOP IMAGE-TO-IMAGE TRANSFER (@2x 1440px -> 2880px wide / 2K bands)
──────────────────────────────────────────────────────────────────────────────────
  Input Reference(s):
    - Band 01 (Anchor): captures/tiles/desktop-band-01.png
    - Bands 02..NN:     captures/tiles/desktop-band-NN.png
                        + variants/tiles/desktop-variant-band-01.png (Style Lock)
  Output:
    - variants/tiles/desktop-variant-band-01..NN.png
    - variants/desktop-variant-fullpage.png (stitched long-form)
    - variants/desktop-variant-2k.png (2752x1536 canonical 2K plate)

PASS 2: MOBILE CROSS-CONDITIONED TRANSFER (@3x 390pt -> 1170px wide / 2K bands)
──────────────────────────────────────────────────────────────────────────────────
  Input Reference(s) — BOTH IMAGES ATTACHED:
    - Image 1 (Mobile Layout & Reflow Authority):
        captures/tiles/mobile-band-NN.png
    - Image 2 (Desktop Variant Visual System & Theme Stance Authority):
        variants/desktop-variant-2k.png (or variants/tiles/desktop-variant-band-01.png)
    - Composite Single-File Conditioning (for single-input CLI routes like gempix):
        variants/tiles/__cond_mobile_band_NN.png (Mobile Capture main canvas with
        Desktop Variant style-strip reference or sequential multi-image ImagePaths)
  Output:
    - variants/tiles/mobile-variant-band-01..NN.png
    - variants/mobile-variant-fullpage.png (stitched long-form)
    - variants/mobile-variant-2k.png (1536x2752 canonical 2K plate)
```

### Why Pass 2 Must Include the Desktop Variant Image
- If Mobile is generated from the Mobile screenshot alone, Nano Banana invents a slightly different shade of accent color, different card border treatment, or different icon style than Desktop.
- If Mobile is generated from the Desktop Variant alone, Nano Banana squashes a `16:9` widescreen layout into a `9:16` portrait frame with microscopic unreadable text.
- By attaching **both** the **Captured Mobile Screenshot** (for `390pt` single-column vertical stacking, `44-52pt` touch target geometry, and mobile card cadence) AND the **Rendered Desktop Variant** (for exact palette, material lighting, wordmark, and bespoke illustration transfer), the Mobile Variant looks unmistakably like the responsive mobile view of the exact same new product.

## 2. The 10 Mandatory Sections of Every Deep Transfer Prompt

Every prompt written to `variants/prompts/<surface>-variant-band-<NN>.md` contains all 10 of these concrete sections:

| # | Prompt Section | What It Locks & Why It Prevents Regression |
| :---: | :--- | :--- |
| **1** | **Use Case, Stance Dial & Orthographic Framing** | Declares `ui-mockup`, the exact `--stance-dial` (`0.15` to `1.00`), the named `--style-stance` (e.g., `nocturnal-obsidian-precision` or `swiss-telemetry-grid`), and strict flat full-bleed orthographic framing (`0` device bezels, `0` angled desks, `0` browser chrome). |
| **2** | **Reference Image Conditioning Roles** | Explicitly tells the model how to read the attached image(s): on Desktop Band `01`, transfer the spatial layout and component complexity from Input Image 1 while applying the new Stance; on Mobile Pass 2, preserve the `390pt` mobile vertical reflow from the Mobile capture while transferring the exact color/material/brand system from the Desktop Variant reference. |
| **3** | **Textural & Material World (Voice 1)** | Physical substrate description (e.g., matte PVD carbon aluminum `#090D12` with `1px` specular top rim, or pure `#FFFFFF` gallery plane with brushed 304 steel `#F1F5F9` containers), light direction, shadow falloff, and zero plastic AI sheen. |
| **4** | **Live Google Fonts & 4-Surface CSS-to-2K Scale Lock (Voice 2)** | Embeds the live-ranked Primary Headline font + Web-Safe Accessible Companion Body font from `recommend_google_fonts.py` + `font_scale_and_pairing.py`, describing physical letterform anatomy (aperture, stroke contrast, terminals, x-height) AND exact viewport-to-2K canvas height ratios (`desktop-web`: `1440x810 @1.91x`, `H1` `6.0%-7.4%` H, `Body` `16-18px` / `2.0%-2.2%` H; `mobile`: `390x844 @3.94x`, `H1` `3.3%-4.0%` H, `Body` `16pt` / `4.1%` W, touch controls `>= 44-52pt`). |
| **5** | **8-Token WCAG-Verified Chromatic System** | Specifies all 8 hex tokens (`bg_primary`, `bg_elevated`, `text_primary`, `text_secondary`, `accent_primary`, `accent_on_primary`, `accent_secondary`, `border_hairline`) pre-audited for WCAG 2.2 AA contrast (`>= 4.5:1` body, `>= 3.0:1` UI borders) and $\Delta E^*_{ab}$ separation from the original site's `avoid_bg_colors` and `avoid_text_colors`. |
| **6** | **Frontend Developer Grid & Optical Padding (Voice 3)** | Locks exact CSS Grid column splits observed in the source band (`12-col`, `50/50 split`, `3-col bento`, `4-col footer`), `1px` crisp borders, exact corner radii (`0px`, `8px`, `12px`), `2:1` L/R optical pill padding (`42-48px` height, `20-28px` L/R padding), `tabular-nums` alignment, and `0` middle dots (`·`) between nav links. |
| **7** | **Observed Visual & Interactive Complexity Inventory (Anti-Regression Lock)** | Lists every structural and interactive element detected in that exact band (`tabs`, `tables`, `codeSamples`, `canvases`, `svgs`, `ctas`, `cards`) plus the agent's visual inspection notes (`--visual-notes`), requiring a **1-for-1 high-craft equivalent** (e.g., if the source band has a 3-tab code sandbox and a real-time throughput chart, the variant MUST render a crisp 3-tab code sandbox and throughput chart in the new style—never regressing into plain text boxes). |
| **8** | **Ordered Region-by-Region Verbatim New Copy** | Provides exact, character-budgeted replacement text for every heading, subhead, nav link, badge, metric readout, and CTA button in that band so Nano Banana renders crisp, legible English typography with zero lorem ipsum or hallucinated gibberish. |
| **9** | **Flutter, Canvas & DOM Artifact Remediation** | Explicitly instructs the model to strip all detected original artifacts (`flt-glass-pane` canvas text softness, Flutter `DEBUG` ribbons, builder watermarks, cookie modals, floating chat widgets, repeated sticky navbars on bands `02..NN`). |
| **10** | **Hard Anti-Clone & Anti-Leakage Exclusions** | Lists the original site's `forbidden_copy_phrases` and `avoid_fonts` to block any accidental carryover, and forbids printing raw hex codes (`#0047FF`), font family names (`Syne`), or `FIG 0.1` labels as visible UI text. |
