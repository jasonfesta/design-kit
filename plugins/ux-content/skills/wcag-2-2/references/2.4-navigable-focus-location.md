# 2.4 Navigable, Focus, and Location

Criteria covered: 2.4.1 through 2.4.13. Use this reference for navigation systems, page templates, headers, footers, sidebars, search, breadcrumbs, sticky UI, focus indicators, link text, headings, and route changes.

## Core Requirement

Users must be able to bypass repetition, identify where they are, find content, understand links and headings, and see where keyboard focus is. Navigation must remain predictable across pages, states, breakpoints, and zoom levels.

## Bypass and Landmarks

2.4.1 requires a way to bypass repeated blocks. Provide skip links, landmarks, or equivalent mechanisms.

Minimum page structure should expose major areas such as header, navigation, main, complementary, search, and footer when present. The first keyboard interaction should make bypass available where repeated navigation precedes main content.

## Page and Route Titles

2.4.2 requires descriptive page titles. Titles must be unique enough to identify the page and should update on SPA route changes, filtered views where the page meaning changes, and major workflow steps.

A useful pattern is: specific page or step first, then product/site name.

## Focus Order

2.4.3 requires a logical focus order that preserves meaning and operability.

Check:

- focus follows the visual/task order;
- focus does not jump behind overlays;
- hidden content is not focusable;
- newly inserted content appears at a logical point;
- responsive reordering does not confuse sequence;
- modals, drawers, menus, and popovers manage focus intentionally.

## Link Purpose

2.4.4 requires link purpose to be clear from link text or its context. 2.4.9 requires link purpose from link text alone at AAA unless ambiguous to all users.

Write links as destinations or actions: "Download 2025 invoice", "View shipping policy", "Edit billing address". Avoid repeated "Read more", "Click here", "Learn more", or icon-only links without names.

When multiple links have the same text, they should usually go to the same destination. If they do not, make the visible or accessible link text distinct.

## Multiple Ways and Location

2.4.5 requires more than one way to locate pages in a set, except for pages that are process steps or result from a process.

Valid mechanisms include navigation, search, sitemap, index, related links, table of contents, and cross-links.

2.4.8 at AAA requires location information. Use breadcrumbs, current navigation state, step indicators, page hierarchy, or clear contextual headings.

## Headings and Labels

2.4.6 requires headings and labels to describe topic or purpose. 2.4.10 at AAA requires section headings to organize content.

Headings should reflect the content that follows. Labels should identify what a control collects or does. Do not use vague headings such as "Information" when the section is specifically "Billing address".

## Focus Visible and Focus Not Obscured

2.4.7 requires visible keyboard focus.

2.4.11 requires the focused item not be entirely hidden by author-created content. 2.4.12 at AAA requires the focused item not be partially hidden.

Common obstructors:

- sticky headers and footers;
- cookie banners;
- chat widgets;
- toasts;
- floating action buttons;
- drawers and side panels;
- virtual keyboards;
- validation summaries;
- scroll snapping.

Reserve scroll margins, avoid covering focused elements, and test at high zoom.

## Focus Appearance

2.4.13 at AAA requires a focus indicator with sufficient area and contrast. Specify focus as a first-class design token, not a browser-reset afterthought.

A robust focus indicator:

- surrounds or clearly marks the focused component;
- contrasts at least 3:1 against adjacent colors or state change;
- has enough thickness or area to be noticed;
- is visible in default, hover, active, selected, error, high-contrast, and forced-color contexts.

## Navigation Pattern Requirements

For menus, sidebars, tabs used as navigation, breadcrumbs, search, and pagination:

- use semantic navigation where appropriate;
- mark current page or step programmatically and visually;
- keep repeated order consistent;
- keep labels concise and descriptive;
- avoid hover-only subnavigation;
- ensure mobile and desktop versions expose equivalent navigation;
- preserve focus and current location after responsive menu changes.

## Acceptance Tests

- Keyboard from page start and use bypass mechanisms.
- Inspect landmarks and heading hierarchy.
- Check page title and SPA title updates.
- Tab through all controls, overlays, and responsive states.
- Review link text in a link list and in context.
- Verify at least two ways to find pages where required.
- Confirm current location cues are visual and programmatic.
- Test focus visibility and obstruction at 200% zoom and 320 CSS px width.
- Measure focus appearance for AAA targets.

## Common Failures

- Skip link absent or hidden when focused.
- SPA route changes update content but not title or focus.
- Focus order follows DOM order that conflicts with visual layout.
- Sticky header covers focused fields during keyboard navigation.
- Multiple "Learn more" links go to different pages.
- Headings chosen for visual size instead of structure.
- Mobile menu lacks items present in desktop navigation.
- Focus indicator removed or too subtle to perceive.
