# 1.1 Text Alternatives

Criteria covered: 1.1.1 Non-text Content (A). Use this reference for images, icons, graphical controls, charts, maps, CAPTCHA, decorative assets, SVG, canvas output, and invisible formatting content.

## Core Requirement

Every non-text item presented to users must have a text alternative that serves the same purpose, unless it fits an allowed exception. The alternative must communicate the function or information, not the file name, visual style, or implementation detail.

## Decision Model

| Non-text content type | Required treatment |
|---|---|
| Informative image | Provide a concise text alternative with equivalent information. |
| Functional image or icon-only control | Provide an accessible name describing the action or destination. |
| Image link with adjacent text | The combined link name must describe the link purpose once, without duplicate noise. |
| Complex image, chart, diagram, map | Provide a short identifier plus a long equivalent near the content, in-page, or through an adjacent link/control. |
| Decorative image | Hide from assistive technology or provide an empty alternative. |
| Formatting/invisible content | Make it ignored by assistive technology. |
| CAPTCHA | Identify the purpose and provide alternatives for different sensory modalities. |
| Sensory experience | Provide descriptive identification of the experience. |
| Test/exercise invalidated by text | Provide descriptive identification, not the answer. |
| Time-based media | Provide descriptive identification here, then meet the media criteria separately. |

## Writing Alternatives

Write the alternative according to user purpose.

Good alternatives answer: What information does this provide? What action does this control perform? What destination does this link open? What result does this visualization show?

Avoid alternatives that repeat nearby text, include "image of" unless the medium matters, expose file names, describe irrelevant decoration, or omit information conveyed by color, labels, position, or symbols in the image.

For product images, describe properties needed for the task: product type, distinctive features, selected variant, damage, state, or context. Do not write a full visual inventory unless the visual details affect the choice.

For icons, use the action or meaning: "Search", "Download invoice", "Error", "Menu expanded". Do not use the icon shape as the name unless the shape is the meaning.

For charts, state the chart type only if useful, then provide the data trend, exact values needed for decisions, axes, units, and any highlighted comparisons.

For maps, provide the equivalent navigational or spatial information: location, route, distance, boundary, nearest landmark, selected region, or available text list.

## Short and Long Alternatives

Use a short alternative when one sentence or phrase can serve the same purpose.

Use a long alternative when the content carries relationships, data, steps, or decisions that cannot fit a short label. The short alternative should identify the content and point users to the long alternative.

Long alternatives may be visible text, expandable text, a table, a transcript-like explanation, an adjacent link, or structured content directly after the visual. The user should not have to guess that the long alternative exists.

## Decorative and Redundant Content

Decorative content is not "unimportant content". It is content that conveys no information, has no function, and is not needed to understand or operate the page.

Hide decorative images and purely visual flourishes. Do not give them names like "spacer", "decorative image", or "background". If the same information is already provided in adjacent text, ensure the alternative does not create duplicate announcements.

## Controls and Inputs

When non-text content is a control, the accessible name must describe the control's purpose. The name must remain accurate across states.

State changes must be exposed separately where needed. For example, a disclosure button's name identifies the controlled section, while its expanded/collapsed state communicates current condition.

Image buttons, icon buttons, SVG buttons, canvas controls, and custom graphical controls all need programmatic names. Visible text should be preferred when possible.

## SVG, Canvas, and CSS Images

SVG that conveys content must expose an accessible name and, if complex, a longer explanation. Decorative SVG must be hidden from assistive technology.

Canvas content that conveys information must have an accessible equivalent outside the canvas or an accessibility-supported implementation. Canvas-only controls are high risk unless equivalent controls and names are provided.

Do not place essential content in CSS background images unless the same content and function are available in text or semantic markup.

## CAPTCHA and Human Verification

A text alternative that says "CAPTCHA" is not enough. The user must know what the challenge is for, and there must be alternative verification methods for different sensory and cognitive needs.

Prefer non-interactive risk analysis, email or device confirmation, passkeys, or support-assisted verification over image/audio puzzles. When a challenge remains, provide multiple accessible modalities and a help path.

## Acceptance Tests

- Every meaningful image, icon, object, SVG, canvas region, and image input has an equivalent name or description.
- Decorative and redundant visuals are ignored by assistive technology.
- Functional graphics announce action or destination, not appearance.
- Complex visuals have a discoverable long equivalent with the same decision-making information.
- Alternatives include information conveyed by color, symbols, labels, and visual relationships.
- CAPTCHA or verification does not depend on one sensory channel.
- Updating an image or data visualization triggers review of its alternative.

## Common Failures

- Missing alternative on meaningful images.
- Empty alternative on functional images.
- File names or vague text such as "photo", "icon", "chart", or "image2".
- Decorative images announced to screen readers.
- CSS background image containing essential text.
- Chart alternative that omits the trend or data needed to act.
- Icon button accessible name that does not match the visible label or current function.
- CAPTCHA with only a visual or audio challenge and no accessible alternative.
