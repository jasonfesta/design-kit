# 1.2 Time-Based Media

Criteria covered: 1.2.1 through 1.2.9. Use this reference for prerecorded and live audio, video, synchronized media, webinars, training, livestreams, embedded media, and media-player requirements.

## Media Alternative Matrix

| Media type | A | AA | AAA |
|---|---|---|---|
| Prerecorded audio-only | Text alternative with equivalent information. | Same as A. | Same as A. |
| Live audio-only | No A/AA requirement. | No AA requirement. | Live equivalent text alternative. |
| Prerecorded video-only | Text alternative or audio track with equivalent information. | Same as A. | Full media alternative. |
| Prerecorded synchronized audio+video | Captions, plus audio description or media alternative. | Captions plus audio description. | Captions, audio description or extended audio description as needed, sign-language interpretation, and full media alternative. |
| Live synchronized media | No A requirement for live captions. | Captions for live audio. | Captions; live audio-only has equivalent live text. |

If media is itself a clearly labeled alternative for text, the related criterion may not require an additional alternative.

## Captions

Captions must include the audio information needed to understand the media: spoken words, speaker identification when not obvious, meaningful sound effects, music cues when relevant, laughter, applause, alerts, and off-screen speech.

Caption quality requirements:

- synchronized with audio closely enough to follow;
- accurate enough to preserve meaning;
- readable at default size and at zoom;
- not obscuring important visual content;
- available through keyboard and assistive technology;
- preserved in embedded players and responsive layouts.

Do not rely on auto-captions without review for accuracy, punctuation, speaker changes, and domain terms.

## Transcripts and Media Alternatives

A transcript for audio-only content must provide equivalent information in sequence.

A full media alternative for synchronized media must include dialogue, meaningful sounds, important visual information, on-screen text, changes of scene, gestures, and any timed interaction needed to achieve the same outcome.

For interactive media, include what the user must do at each timed point and what feedback the system provides.

## Audio Description

Audio description communicates important visual information that is not available in the audio track: actions, expressions, scene changes, text on screen, visual jokes, charts, gestures, and silent demonstrations.

For AA, prerecorded video in synchronized media needs audio description. For A, audio description or a media alternative can satisfy the criterion. For AAA, extended audio description is required when pauses in the original audio are not long enough for necessary descriptions.

Descriptions should not interrupt important dialogue or overload the listener with decorative detail. They must communicate information needed to understand or act.

## Sign-Language Interpretation

For AAA, prerecorded synchronized media must include sign-language interpretation. Specify the sign language expected by the audience, not only the spoken language of the audio. Ensure the interpreter remains visible, synchronized, and large enough to perceive.

## Media Player Requirements

The player must not create barriers while delivering accessible media.

Required behavior:

- keyboard access to play, pause, seek, volume, captions, audio description, transcript, full-screen, and settings;
- visible focus on all controls;
- captions and descriptions can be enabled without a pointer;
- controls have accurate names, roles, values, and states;
- auto-playing audio follows audio-control requirements;
- captions, transcript, and description remain available across breakpoints;
- custom controls expose state changes to assistive technology.

## Live Media

For live streams, plan captioning and alternatives before the event. Provide fallback instructions for caption failure, a way to report accessibility issues during the event, and post-event corrected captions/transcripts when the recording is published.

Live captions should identify speakers and meaningful sounds. Latency should be low enough that users can participate in real time when participation is part of the event.

## Acceptance Tests

- Identify each media item as audio-only, video-only, synchronized, live, or prerecorded.
- Confirm each item has the alternatives required for the target level.
- Check captions against speech and meaningful sounds.
- Check audio description against visual-only information.
- Verify transcripts and media alternatives preserve sequence and outcome.
- Operate all player controls using keyboard only.
- Inspect player control names, roles, values, and states.
- Test captions and media controls at small viewport widths and high zoom.

## Common Failures

- Prerecorded video with captions but no audio description at AA.
- Captions that omit sound effects or speaker identity when needed.
- Transcript that includes dialogue only and misses important visual information.
- Media player controls that require a mouse.
- Captions hidden by full-screen mode, overlays, or mobile layout.
- Audio description track listed but not synchronized or not selectable.
- Live event recording published without corrected captions.
- Auto-captions treated as sufficient without review.
