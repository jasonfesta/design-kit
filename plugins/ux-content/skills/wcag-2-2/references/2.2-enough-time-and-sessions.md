# 2.2 Enough Time and Sessions

Criteria covered: 2.2.1 through 2.2.6. Use this reference for timers, sessions, carousels, auto-updating content, dashboards, exams, forms, authenticated flows, interruptions, and timeout warnings.

## Core Requirement

Users must have enough time to read, understand, operate, recover, and complete tasks. Time pressure can block users with motor, cognitive, visual, language, attention, or assistive-technology needs.

## 2.2.1 Timing Adjustable

When a time limit is set by the content, users must be able to turn it off, adjust it, or extend it before it expires, unless an exception applies.

Valid exceptions are narrow: real-time events where the time limit is essential, time limits longer than 20 hours, or cases where changing the limit would invalidate the activity.

Design obligations:

- Avoid time limits where possible.
- Warn users before expiry.
- Provide a simple extension control.
- Preserve data if the time limit expires.
- Make extension controls keyboard accessible and screen-reader understandable.

## 2.2.2 Pause, Stop, Hide

Users need control over moving, blinking, scrolling, or auto-updating information that starts automatically, lasts more than five seconds, and appears with other content, unless the motion/update is essential.

For auto-updating content, users must be able to pause, stop, hide, or control update frequency unless the update is essential.

Applies to:

- carousels and slideshows;
- tickers and marquees;
- auto-refreshing feeds;
- live dashboards;
- animations and loaders that persist;
- blinking notifications;
- chat or comment streams.

## 2.2.3 No Timing

At AAA, timing must not be an essential part of the event or activity except for non-interactive synchronized media and real-time events. Prefer untimed alternatives for quizzes, forms, checkout, onboarding, and account tasks.

## 2.2.4 Interruptions

At AAA, users must be able to postpone or suppress interruptions except emergencies.

Interruptions include popups, chat prompts, marketing modals, noncritical alerts, notification banners, automatic tips, and proactive assistance. Provide controls for frequency, timing, and dismissal persistence.

## 2.2.5 Re-authenticating

At AAA, when an authenticated session expires, the user must be able to re-authenticate and continue without losing data.

Design and implementation requirements:

- Save draft data before session expiry.
- Return users to the same task and state after login.
- Preserve uploaded files, selections, filters, and form entries where feasible.
- Explain what happened and what remains safe.
- Avoid forcing users to restart multi-step flows.

## 2.2.6 Timeouts

At AAA, users must be warned about the duration of any inactivity timeout that could cause data loss, unless the data is preserved for more than 20 hours.

The warning must be available before the timeout affects the user. Put timeout information near the task entry point or in a persistent, findable location. Do not hide it only in legal text.

## Session and Timeout Design

For authenticated web apps:

- State the inactivity timeout duration before high-effort tasks.
- Warn before expiry with enough time to act.
- Allow keyboard and assistive-technology users to extend the session.
- Keep focus behavior stable when warnings appear.
- Avoid interrupting typing or screen reader reading order.
- Save progress automatically when possible.
- After re-authentication, restore the task, not just the home page.

## Auto-Updating Dashboards and Feeds

Provide controls for pause, resume, refresh now, and update frequency. Announce important updates without flooding assistive technologies. Do not move focus when new items arrive unless the user requested that behavior.

For live regions, use polite announcements for nonurgent status and assertive announcements only for urgent changes. Avoid announcing every minor refresh.

## Carousels and Rotating Content

If rotating content starts automatically, provide a visible and keyboard-operable pause/stop control before or near the carousel. Stop auto-advance when users interact with the carousel unless restarting is user requested.

Do not make users chase moving controls. Slide content must remain accessible when paused.

## Acceptance Tests

- Identify every timer, auto-refresh, animation, interruption, and session expiry.
- Verify users can turn off, adjust, or extend time limits where required.
- Test pause/stop/hide for moving and auto-updating content.
- Confirm interruptions can be postponed or suppressed for AAA targets.
- Expire an authenticated session mid-task and verify data is preserved after re-authentication.
- Confirm inactivity timeout duration is disclosed where it can cause data loss.
- Test all controls with keyboard and screen reader.

## Common Failures

- Session expires and discards a completed form.
- Timeout warning appears visually but is not announced or focusable.
- Carousel auto-advances with no pause control.
- Auto-refresh moves focus or changes reading order unexpectedly.
- Marketing modal interrupts a task with no persistent opt-out.
- Timer extension requires precise pointer use.
- Users are told a timeout exists only after data has been lost.
